# Contributing to GutSaga

Thanks for helping. GutSaga is a custom saga log for World of Warcraft Forever and Classic: a Lua addon, a Go companion, a Go API, and Smia MCP tools. Player-facing strings stay Norwegian. Issues, pull requests, and these docs are English.

By participating you agree to the [Code of Conduct](CODE_OF_CONDUCT.md). Report vulnerabilities the way [SECURITY.md](SECURITY.md) describes. Do not open a public issue for a security report.

## What lives where

| Area | Path | Notes |
|---|---|---|
| API | `api/` | HTTP server, migrations, Postgres store. `package main`. |
| Companion | `cmd/gutsaga` and `internal/` | Desktop program. Installs the addon, Smia login, sync. |
| Addon | `addon/GutSaga` | Lua, TOC files, artwork. Embedded into the companion by `addon/embed.go`. |
| Smia tools | `smia/wow-mcp` | MCP graphs. They call the API with `GUTSAGA_ADMIN_TOKEN` from the hub environment. |
| Contract | `internal/contract`, `docs/` | Shared JSON shapes. Change the docs when the wire format changes. |

The API and the companion are one Go module (`go.mod` at the repository root). Go 1.22.

## Local development

You need Docker, Go 1.22, and (for the addon) Lua 5.1 and [luacheck](https://github.com/lunarmodules/luacheck). A WoW client is only needed when you want to see the addon in game. Ports `5432` and `8080` must be free.

### API and Postgres

From the repository root:

```bash
make dev
```

`make dev` starts Postgres 16 and the API with `docker compose`, waits for `http://localhost:8080/healthz`, and seeds three party sagas in Elwynn Forest. Running it again updates those same titles. `make down` stops the containers. `docker compose down -v` deletes the database volume.

Compose sets local-only values: database `gutsaga` / user `gutsaga` / password `gutsaga`, `ADMIN_TOKEN=dev-admin-token`, and `IMAGE_URL_SECRET=dev-image-url-secret`. Those are for a laptop. Generate real values with `openssl rand -hex 32` for any shared or public server. Copy `.env.example` to `.env` if you want a Discord webhook locally. `.env` is gitignored. Do not commit it.

`make dev` uses real Smia login. The API container must reach `https://smia.tools`, and the account must be a member of the hub **wow**. To skip the browser while Smia is down, set `SMIA_AUTH_MODE=dev` and `SMIA_DEV_TOKEN=dev-token` on the API, and `GUTSAGA_DEV_TOKEN=dev-token` on the companion.

Apply migrations by starting the API. They run on startup. SQL files are `api/migrations/`.

### Companion

The embedded addon is what players get. While you edit Lua, point the companion at the working tree:

```bash
GUTSAGA_ADDON_SRC=addon/GutSaga go run ./cmd/gutsaga --api-url http://localhost:8080 --client classic_era
```

`--client` is `forever` (default), `retail`, `classic_era`, or `classic`. The same values exist as `GUTSAGA_CLIENT`. `--wow-path` or `GUTSAGA_WOW_PATH` points straight at the flavor directory (`_classic_era_`, `_classic_`, `_retail_`, `_anniversary_`) when discovery picks the wrong one.

The longer click-by-click for retail and Classic, including the three seeded sagas, is in the README under [Lokal testing](README.md#lokal-testing).

### Addon

Edit `addon/GutSaga`. Keep `addon/INTERFACE` and the `.toc` files on the same interface numbers. `luacheck` uses `.luacheckrc` (Lua 5.1, WoW API in `read_globals`).

```bash
luacheck addon
lua5.1 addon/objectives_test.lua
lua5.1 addon/chains_test.lua
```

`addon/GutSaga/GutSagaData.lua` is generated by the companion. It is excluded from luacheck. Do not hand-edit it as if it were source.

### Tests

API tests migrate and then `TRUNCATE` the database. They refuse to start unless the database name contains `test`, so they cannot wipe the `gutsaga` database from `make dev`.

```bash
docker compose up -d postgres
docker compose exec postgres createdb -U gutsaga gutsaga_test
export DATABASE_URL=postgres://gutsaga:gutsaga@127.0.0.1:5432/gutsaga_test?sslmode=disable
go test ./...
```

`createdb` fails if `gutsaga_test` already exists; that is fine, use the existing database. `make test` runs `go test ./...` plus the two Lua files. It does not run luacheck. CI does: Go tests, a Windows companion build, luacheck, and both Lua files. See `.github/workflows/ci.yml`.

Format Go with `gofmt` before you commit.

## Pull requests

1. Fork the repository and branch from `main`.
2. Keep the change focused. A bug fix and an unrelated refactor belong in separate pull requests.
3. Run the tests that cover what you touched. CI runs the full set on the pull request.
4. Open a pull request using the template. Describe the behavior change and how you checked it.
5. A maintainer reviews, CI is green, and then it merges.

GitHub will ask a maintainer to approve Actions the first time you contribute.

## Commit messages

Use [Conventional Commits](https://www.conventionalcommits.org/):

```text
type(scope): subject
```

The subject is imperative, lowercase, and has no trailing period. Add a body when the subject does not say why.

| Type | Use |
|---|---|
| `feat` | New behavior |
| `fix` | Bug fix |
| `docs` | Documentation only |
| `refactor` | Code change that does not change behavior |
| `test` | Tests only |
| `ci` | GitHub Actions or other automation |
| `build` | Build system or dependencies |
| `chore` | Everything else that is not a release |

Scope is optional. Prefer `api`, `companion`, `addon`, `mcp`, `docs`, or `ci`.

```text
fix(addon): keep the last readable roster when names are secret in combat

feat(api): reject a completion while a required saga is still open
```

Dependabot opens dependency updates against the root Go module (that covers `api/` and the companion) and against GitHub Actions. See `.github/dependabot.yml`.
